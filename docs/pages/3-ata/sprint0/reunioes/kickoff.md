## 2. Resumo da Reunião
#### 2.1. Objetivo da Reunião

Realizar o kickoff do projeto com o stakeholder Alexandre Carreiro: apresentar a equipe e o fluxo de acompanhamento das entregas via GitHub Projects, e iniciar a elicitação dos requisitos e das dores de negócio do escritório de advocacia para definição do escopo do MVP a ser desenvolvido no prazo de 4 meses.

#### 2.2. Pautas da Reunião
| Pauta                                                     |
| --------------------------------------------------------- |
| Apresentação da Equipe e do Stakeholder                   |
| Apresentação do GitHub Projects                           |
| Elicitação de Requisitos                                  |

#### 2.3. Decisões Importantes

- O GitHub Projects será a ferramenta central de acompanhamento do desenvolvimento, organizado em colunas (a fazer, em progresso, em homologação e finalizado); cada entrega passa por homologação do Alexandre antes de ser considerada finalizada.
- Comunicação sobre novas homologações e alterações será feita via WhatsApp, em um grupo a ser criado com o Alexandre e toda a equipe.
- Prazo do projeto: 4 meses. O escopo priorizará um MVP viável dentro desse período, sem deixar de atender às necessidades essenciais do cliente.
- Escopo identificado em duas frentes: (1) site institucional/informativo (apresentação do escritório, história, equipe, artigos e materiais informativos — sem captação de clientes, conforme regras da OAB); (2) painel interno de gestão de processos jurídicos (estilo CRM).
- Principal dor de negócio identificada: controle de prazos processuais (ex.: risco de revelia por perda de prazo), sendo essa a prioridade do painel de gestão.
- Alexandre enviará, até o dia seguinte, um documento detalhando sua visão de produto e, se possível, materiais de um projeto anterior que ele já havia iniciado (referência visual/paleta de cores).
- Sistemas de mercado citados como referência/benchmark: Astrea, ADVBox e JusDoc (petições via IA) e Mapa Fiscal RTC; Data Jud e Jus Brasil foram citados como possíveis fontes de dados processuais para uma fase futura, fora do escopo do MVP.
- Próximos passos: consolidar os requisitos levantados, apresentá-los para validação do Alexandre e iniciar a prototipação de cada requisito (ex.: página de cadastro), com validação visual do cliente antes do desenvolvimento.
